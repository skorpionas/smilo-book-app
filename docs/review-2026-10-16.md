# Review 2026-10-16 — security and UI/UX

Owner feedback round: pet-first directory, per-pet prices, a security check of every endpoint, and a UI/UX
review for the three devices the salon actually uses (iPhone, iPad, laptop).

### Fixed in PR #6

1. **Reset-link host injection (medium).** `requestPasswordReset` built `redirectTo` from `X-Forwarded-Host` /
   `Host`. Supabase's redirect allow-list blocks foreign hosts, but the app must not rely on that. The origin
   now comes from `NEXT_PUBLIC_SITE_URL`, else Vercel's production / deployment URL.
2. **Open redirect after login (low).** Browsers drop tabs / newlines and treat `\` as `/`, so
   `next=/%09/evil.com` passed the `//` check. Control characters and backslashes are now refused anywhere.
3. **Function surface for anon (hygiene).** `f_unaccent`, `f_search_norm` and three trigger functions were
   executable by `anon`. Revoked; default privileges no longer grant new functions to `anon` / `PUBLIC`.
   pgTAP asserts that anon can execute no function in `public`.
4. **Headers.** `Strict-Transport-Security: max-age=63072000; includeSubDomains`,
   `Cross-Origin-Opener-Policy: same-origin`.

### Guard rails added

- E2E `security.spec.ts`: every private route (incl. `/pets/[id]`, `/styleguide`) redirects without data; an
  action POST without a session gets no data; headers present; a crafted `next=` cannot leave the site.
- Unit `actions-require-user.test.ts`: fails if any new Server Action forgets `requireUser()`.
- pgTAP `06_pet_services`: RLS on `pet_services`, cross-owner service refused, anon function surface empty.

### Accepted / later

- CSP keeps `script-src 'unsafe-inline'` (Next.js inline bootstrap). A nonce-based CSP forces every page to
  render dynamically — already the case here — so it is a reasonable Iteration 2 hardening step.
- Login brute force: Supabase rate-limits sign-ins per IP; server-side calls share Vercel's IPs, so the limit
  is effectively global (slows an attacker, can briefly lock the owner out). Acceptable for one account.

## UI/UX review

Method: every main screen rendered against seed data on **iPhone 13 (390×844)**, **iPad portrait (820×1180)**,
**iPad landscape (1180×820)** and **laptop (1280×800)** — 50 screenshots, generated by
`tests/e2e/screens.spec.ts` (label a PR `ui-screens` to publish fresh ones to the `ui-screens` branch). Judged
against the design principles in `docs/design.md`, Apple HIG (touch targets, sidebars vs tab bars, sheets on
iPad) and WCAG 2.1 AA.

### What already works well

- One accent, calm surfaces, status = icon + word + tint; groomer colours never carry text.
- Touch targets ≥ 44 px, 16 px inputs (no iOS zoom), thumb-zone primary actions, FAB above the tab bar.
- Day view: two groomer lanes, now-line, highlighted allergy / behaviour icons on cards.
- Designed empty, loading and error states everywhere.

### Recommendations not done in this PR

1. **Complete a visit** ("Užbaigti vizitą") is still missing — planned for week 3; on the booking detail it
   should be the primary button once the visit has started.
2. **Date field format**: native `<input type=date>` follows the device language (shows `10/16/2026` on an
   English iPad). Either set the iPad to Lithuanian or replace it with the month mini-calendar (Could).
3. **Swipe between days** on the day view (iPad / iPhone), in addition to the arrows.
4. **Booking detail on iPad landscape**: show it as a popover next to the card instead of a full-height panel.
5. **Dark mode switch** in Nustatymai (now follows the OS only) — one of the open design questions from PR #2.
6. **Week grid on iPad landscape**: consider hiding Sunday when no groomer works that day to give six days more
   width.
